# 架构文档图种规范

> 每个图种：回答什么问题 / 放哪一节 / 必备元素 / 常见错误 / 与正文的一致性要求。
> 画法（SVG 语法、风格、连接器六条硬规则、复杂度预算）以 `diagram-design` 技能为准，本文件只管「画什么、放哪、怎么算合格」。

## 1. 业务/价值链图

- **回答**：这套系统为谁、在哪几个环节创造什么价值。
- **位置**：概述之后、领域建模之前。
- **必备**：阶段列；每阶段「用户输入 / 系统动作 / 产出 / 门槛」；优先级标记；角色标注。
- **常见错误**：把内部模块画成业务环节；只有「什么」没有「谁」；阶段间没有交付物。
- **一致性**：图上的阶段名 = 正文 §2 的阶段名；图上产物 = 正文「产物」表。

## 2. 领域模型（ER）

- **回答**：系统的名词有哪些、谁是聚合根、谁属于谁、哪些是真源。
- **位置**：业务分析之后、逻辑架构之前。
- **必备**：实体框（名 + 字段）；主键 `#`、外键 `→`；关系两端基数（写法全图统一）；真源标注；过程数据（日志/会话）明确排除或斜体注记。
- **常见错误**：画成物理表结构（列类型/索引塞满）；实体数超预算；每条外键都画箭头导致蜘蛛网；没有基数。
- **一致性**：实体名 = 数据集合名；实体数 = 正文「领域概念速览」行数；不变量在正文单列。

## 3. 逻辑架构图

- **回答**：有哪些组件、谁调用谁、边界在哪。
- **位置**：领域建模之后。
- **必备**：分层/分区（每层有真实含义）；组件框；方向明确的连线；外部系统单独标识（如虚线/灰色）；调用方向单一（防环）。
- **常见错误**：所有层画成同样方框；把部署信息（主机名/端口/副本）塞进来；双向箭头模棱两可；跨层乱连。
- **一致性**：图上一级组件 = §5 组件清单第一层；连线方向 = 正文「模块间唯一调用方向」段。

## 4. 组件清单（分层表/图）

- **回答**：代码里到底有哪些模块、怎么切分、谁负责。
- **位置**：紧接逻辑架构。
- **必备**：层 → 组件 → 子组件（文件/操作级）三列；每行一句话职责；状态；分册链接。
- **常见错误**：只有名字没有职责；层与组件混在一列；粒度到不了文件/操作就不算「清单」。
- **一致性**：清单行数 = 分册数；每个链接可打开；状态词在词表内。

## 5. 核心流程时序图

- **回答**：一次请求按时间顺序经过谁、哪一步必须人工确认、失败怎么走。
- **位置**：流程/交互一节。
- **必备**：生命线（≤5 条）；消息箭头只向下；返回用虚线；激活条；条件片段（`opt`/`loop`/`alt`）；验收点标注。
- **常见错误**：消息箭头向上；用自由飘的箭头簇表示 if/else；片段框贴住生命线；嵌套超过 1 层。
- **一致性**：生命线 = 正文角色表；每个验收点在正文有判据与失败路径。

## 6. 状态机

- **回答**：一个对象有哪些状态、什么条件才允许流转、终止态是什么。
- **位置**：流程之后或模块详设。
- **必备**：状态；迁移；守卫条件；终止/取消态；非法迁移的行为。
- **常见错误**：状态与阶段混用；迁移没有守卫；没有取消/异常终态。
- **一致性**：状态名 = 代码枚举；每个迁移在正文有触发事件。

## 7. 数据流图

- **回答**：数据从哪来、经过什么加工、落到哪、合规边界在哪。
- **位置**：数据/集成一节。
- **必备**：数据源、加工、存储、流向、数据形态（原始/结构化/产物）、合规边界。
- **常见错误**：与时序图重复；不标数据形态；把控制流画成数据流。
- **一致性**：存储名 = 真源表；边界 = §11 安全边界。

## 8. 物理部署图

- **回答**：装在哪、什么边界、几个副本、什么版本、走什么协议。
- **位置**：逻辑架构与流程之后。
- **必备**：分区（环境/网络/信任边界）；节点；部署物（**带版本**）；副本数徽标；协议 + 端口；出网唯一口。
- **常见错误**：把逻辑架构图加上主机名；分区只是视觉分组；**连线停在分区边界而不是节点本体**；部署物没版本。
- **一致性**：节点/版本 = 部署清单；分区 = §7 部署表；唯一出网口 = §11。

## 9. 决策对照（通常用表）

- **回答**：关键技术选型的取舍。
- **位置**：决策一节。
- **不推荐画图**：3 列以内能说清时用表；图只在「多方案多判据」且读者真需要空间比较时用。
- **一致性**：每个选项 = 决策表备选列；结论 = D 编号。

---

## 最小图集与数量控制

- 最小集：逻辑架构 + 领域模型 + 核心流程时序 + 状态/流转 + 物理部署。
- 业务价值链、数据流、决策对照可先用表；读者真需要时再画。
- 一份架构文档 5–8 张图为宜；超过 10 张读者记不住，拆成总览 + 专题。

## 图文一致性条款（逐条可检）

1. **术语**：图内标签 = 正文术语表 = 代码模块名；缩写首次出现有全称。
2. **数量**：图上实体/生命线/验收点数与正文提到的数字一致；数字只在正文定义一次，图引用它。
3. **边界**：图上每个分区/层/边界，正文必须有一节解释它；正文提到的东西图上必须找得到。
4. **图题/图注**：图题说对象与范围；图注说取舍与依据（为什么这样画），不重复图内文字。
5. **复用图**：必须写 delta（与当前设计哪里不同），否则读者会把旧图当现状。
