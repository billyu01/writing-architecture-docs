# 图语义与绘图规范（一张图只回答一个问题）

## 1. 图种与唯一问题

| 图 | 只回答的问题 | 不该出现 |
|---|---|---|
| 系统上下文图 | 系统边界外有哪些角色/系统、走什么协议 | 内部模块、领域聚合 |
| 限界上下文图 | 有哪些领域边界、上下文之间什么关系 | 系统调用、部署节点、消息中间件 |
| 核心领域实体关系图（ER View） | 实体/聚合之间怎么关联、基数与约束 | 仓储/工厂/领域服务等概念 |
| DDD 概念图 | 聚合、实体、值对象、仓储、服务、事件如何协作 | 全部业务字段、部署信息 |
| 逻辑架构图 | 有哪些模块、职责与依赖方向 | 部署节点、运行时进程 |
| 进程视图 | 有哪些进程、并发/异步/锁/恢复 | 代码目录、领域概念 |
| 开发视图 | 代码怎么分层、依赖与构建测试 | 部署拓扑 |
| 部署图 | 部署单元/副本/网络/存储 | 进程内代码层（如 infra 适配器） |
| 时序图 | 一次请求的消息顺序、事务边界、异常分支 | 全量错误码表 |
| 状态机图 | 对象有哪些状态、迁移与守卫 | 跨对象流程 |
| 事件流转图 | 事件产生→领取→发送→重试/死信 | 同步调用链 |
| 账本/对账流程图 | 变更→流水→余额→重算→差异修复 | 部署信息 |

## 2. 线型与图例（全文档统一）

- 实线箭头：同步调用；虚线箭头：异步事件/消息；双线或标注：数据复制。
- 颜色：墨色=内部；链接蓝=HTTP/外部调用；强调色=核心链路/焦点（全图 ≤2 处）。
- 边界：虚线框=系统/上下文/分区边界；实线框=组件/节点。
- 每张图必须有图例，说明线型、颜色、形状；图例放画布底部或右侧空白，不压节点。
- 图中不得出现没有解释的缩写；不得把「共享内核/发布语言」画成独立服务或消息总线——它们是关系模式，不是部署组件。

## 3. 硬性禁止

1. 部署图出现进程内代码层（infra 适配器、repository、domain service）作为独立 Pod/节点。
2. 限界上下文图混入系统调用、部署节点、消息中间件。
3. 时序图不画事务边界、不画异常/重试分支。
4. 一张图同时表达两个以上视图（如领域关系 + 部署）。
5. 图例与正文语义不一致（实线/虚线含义在不同图里变化）。

## 4. 必须补充的图（按需）

- 状态机：券、充值单、导入批次（状态 ≥4 个的对象）。
- 事件流转：outbox 领取/租约/重试/死信。
- 账本/对账：积分流水→余额→重算→差异修复。
