
# 架构配图总览（原配图技能合并）

## 这是什么

> 路径相对技能根目录；画法细节参考外部 `diagram-design` 技能。

把「画一张好图」和「把图可靠地放进文档并长期维护」分开。**画**交给 `diagram-design` 技能；**用**——图种选择、与章节对齐、派工、内嵌构建、几何验收、修复回路——由本技能负责。

**一句话分工**：`diagram-design` 对一张图负责；本技能对「图在架构文档里长期正确」负责。

## 何时使用

- 架构文档要新增一套图（领域/逻辑/时序/部署）。
- 已有图被反馈：看不到、被裁切、有滚动条、多图叠加、文字出框、连线断开或指向错、样式串了。
- 要把多张 SVG 内联进一份 HTML 或 Markdown，并声明「可重建」。
- 要检查图与正文的术语、数量、边界是否一致。

**不使用**：只画一张与文档无关的示意图（直接用 `diagram-design`）；做数据可视化图表（用图表类技能）。

## 三条前置原则

1. **图不是插图，是约束画**：图上每条边界、编号、数量，正文与实现都要能对上；对不上就是缺陷。
2. **先文字后图**：先确定这一节要回答读者什么问题、图要钉住哪条约束；说不出来就不要画（用表或段落）。
3. **图必须四件套**：图号 + 图注 + 源文件 + 图索引行。只给图或只给链接都不算交付。

## 图种与最小图集

| 图种 | 回答什么问题 | 通常放哪节 | 必备元素 | 常见错误 |
|---|---|---|---|---|
| 业务/价值链 | 为谁、在哪些环节创造什么价值 | 概述之后、领域之前 | 阶段 + 每阶段价值/产物 + 优先级 | 把内部模块画成业务环节 |
| 领域模型（ER） | 名词有哪些、谁是聚合根、谁属于谁 | 业务分析后、逻辑架构前 | 实体 + 字段 + 主外键 + 基数 + 真源标注 | 画成物理表；实体超预算 |
| 逻辑架构 | 有哪些组件、谁调用谁、边界在哪 | 领域建模后 | 分层分区 + 组件 + 有向连线 + 外部系统标识 | 每层同样方框；混入部署信息 |
| 组件清单 | 代码有哪些模块、怎么切 | 紧接逻辑架构 | 层→组件→子组件三层 | 有名字没职责；层与组件混列 |
| 核心流程时序 | 一次请求按时间经过谁、哪步人工 | 流程/交互 | 生命线、消息、激活条、条件片段、验收点 | 箭头向上；分支不用片段框 |
| 状态机 | 对象有哪些状态、什么条件可流转 | 流程后/模块详设 | 状态、迁移、守卫、终止态 | 状态与阶段混用；无守卫 |
| 数据流 | 数据从哪来、怎么加工、落到哪 | 数据/集成 | 源、加工、存储、流向、合规边界 | 与时序图重复；不标数据形态 |
| 物理部署 | 装在哪、什么边界、几副本、版本 | 逻辑与流程之后 | 分区、节点、部署物（带版本）、副本、协议端口 | 用逻辑架构加主机名；连线停在分区边界 |
| 决策对照 | 选型取舍 | 决策节 | 选项、判据、结论、影响 | 用图代替表 |

**最小图集**：逻辑架构 + 领域模型 + 核心流程时序 + 状态/流转 + 物理部署（业务价值链可先用表）。超过 8 张要警惕，读者记不住。

**与正文的一致性条款**：
- 术语表先行；图内标签、正文小标题、代码模块名三处同名同大小写。
- 图上数量要能被正文复述（N 个实体、M 条生命线、K 个验收点）。
- 图的边界就是文档的边界：图上画的分区/层，正文必须有一节解释。
- 图题说「是什么」，图注说「为什么/依据」；解释不要塞进画布。

## 画图十步法

| # | 步骤 | 检查点（不合格退回） |
|---|---|---|
| 1 | 判断要不要画（读者问题、钉哪条约束、表能否替代） | 说不出读者问题 → 改表 |
| 2 | 定图种（先选语义模式，再落到视觉类型） | 类型参考已读 |
| 3 | 定内容与预算（节点/连线/分区清单，标 1–2 焦点） | 在复杂度预算内；超了拆总览 + 详图 |
| 4 | 定画布尺寸（文档内联约 960–1200 宽；宽图 1200–1400） | 宽高比接近嵌入容器 |
| 5 | 读 `diagram-design` 风格总纲 + 类型参考 + 模板 | 颜色/字体全部取自 style-guide |
| 6 | 画：背景 → 分区 → 连线 → 盒子 → 标签 → 图例 | 连线先画；文字最后 |
| 7 | 机器自检：`self_check.py` + 本技能脚本 | 全 `OK`，且几何检查也过 |
| 8 | 视觉终检：无头浏览器截图整图 + 局部裁剪 + 窄屏 | 亲眼确认无重叠/无裁切/无溢出 |
| 9 | 导出 SVG/PNG（按 `diagram-design` 导出流程） | 导出物 viewBox 与源一致 |
| 10 | 嵌入文档：占位符构建或内联；前缀化；更新索引 | 构建断言通过；浏览器完整可见 |

**派工书七段**（交给子代理画图时必须给全）：技能加载（风格总纲/类型参考/模板/既有同类参考/自检命令）→ 图内容与硬数字预算 → 语义要求（焦点、标记、图题原文）→ 产出路径 → 自检清单 → 回执格式（≤12 行）→ 中断兜底（先落盘再汇报）。模板见 `references/drawing-pipeline.md`。

## 嵌入与构建

- **内联 SVG，不用 iframe**：iframe 会出滚动条、被裁切、打印丢失。
- **占位符构建**：模板里写 `<!--INLINE:<slug>-->`，构建脚本把 SVG 塞进去，并给 **id 和 class 都加图前缀**；同步改 `url(#…)`、`href="#…"`、`aria-labelledby`。只加 id 前缀不够——`<style>` 是全局的，短类名（`.ttl`/`.nm`/`.mg`）会跨图互相覆盖。
- **视口换算**：容器高度 = 目标宽度 × `viewBox` 高 ÷ `viewBox` 宽；不要写死高度。
- **构建断言**：无未替换占位符、整页 id 唯一、图数正确、连跑两次字节一致。
- **构建脚本与模板必须与产物同生命周期**：脚本被删 = 「可重建」承诺失效。
- 详细步骤与清单见 `references/embedding.md`。

## 逐图验收（每张图单独签字，禁止批量放行）

每张图必须单独走完：内容正确 → 关系画全 → 几何干净 → 人眼复核 → 记入验收表。
- **内容正确**：元素、命名、方向与正文一致；DDD 图必须画出「仓储管理聚合 / 工厂创建聚合 / 领域服务依赖聚合 / 聚合发布事件」四类关系，不能只把元素堆在图里。
- **关系画全**：上下文图必须标方向与关系模式（共享内核/客户-供应商/防腐层/发布语言）；部署图必须能从每根线追踪到目标节点。
- **几何干净**：没有连线重叠、标签压节点、文字出框、页面滚动。
- **人眼复核**：整图 + 局部裁剪 + 窄屏截图，逐张确认。
- **验收表**：图号/图名/检查项/结果/截图路径，作为交付证据。

## 验收（进入文档前必须全过）

| # | 检查 | 怎么查 |
|---|---|---|
| 1 | 可访问性契约 | `role="img"` + `aria-labelledby` 指向存在的 title/desc |
| 2 | 图内文字不溢出 | 按中文字号、西文 0.6×字号估宽，对比所属盒子/画布边界 |
| 3 | 连线端点落在节点边界 | 逐条解析 path 起止点，与节点矩形四边比对（容差 ≤3px） |
| 4 | 标签遮罩不压线、不压节点 | 遮罩与线/后画盒子求交 |
| 5 | 跨图 id 不重复 | 整页统计；`marker`/`title`/`desc` 是高发项 |
| 6 | 跨图 class 不冲突 | 统计每个内嵌 `<style>` 的同名选择器；不一致即失败 |
| 7 | 页面不滚动/不裁切 | 渲染后比较 scrollWidth/clientWidth；容器高度按 viewBox 换算 |
| 8 | 图文一致 | 图内文本与正文术语表、数量、边界逐条对照 |

机器检查：
```bash
python3 scripts/check_architecture_diagrams.py <文档.html 或 assets 目录>
```
人工终检：按目标宽度截图 → 整图看一遍 → 按分区/图例/最长标签裁剪放大 → 窄屏再截一次。

修复手法库（症状 → 根因 → 修法）见 `references/qa-checklist.md`。

## 修复回路

1. **定位**：先问「症状是哪一类」——看不到 / 滚动 / 叠加 / 文字超框 / 连线断——再对到渲染层、样式层、几何层、资产层。
2. **只改源**：改图源 HTML → 重导 SVG → 重跑构建；不在生成物里手补。
3. **升级检查器**：每次新症状变成一条自动检查，下次不再靠眼睛。
4. **复验**：同一套脚本重跑 + 截图对比；修完更新图索引与修订史。

## 反模式与红旗

- 图只给链接、不给内嵌；或内嵌但没图号/图注/索引。
- 多张 SVG 内联却不给 class 加前缀（症状：第 N 张图的文字叠到上一张）。
- 连线靠目测「差不多」（差 4–28px 就是断开）。
- 用固定 iframe 高度装不同长宽比的图（必裁切）。
- `viewBox` 与导出尺寸不一致；导出后 `width="100%"` 未处理。
- 字号靠肉眼硬塞（溢出应改文案/加盒子，最后才减字号）。
- 构建脚本不在仓库里，却声称可一键重建。
