# 逐图验收清单

> 用法：每张图一行，逐项打勾；任一硬项不过，不许进交付。

## DDD 领域模型图

- [ ] 聚合根、实体、值对象、领域服务、仓储、工厂、领域事件都出现，且构造型正确
- [ ] 聚合到内部实体/值对象有组合/聚合关系
- [ ] 仓储到对应聚合有「管理」关系
- [ ] 工厂到对应聚合有「创建」关系
- [ ] 领域服务到依赖的聚合有「依赖」关系
- [ ] 聚合到领域事件有「发布」关系
- [ ] 方法与字段只保留关键项，不堆代码
- [ ] 与正文 4.x 的表格逐项对得上

## 图体系（至少覆盖）

- 系统上下文图（客户端 → 系统边界 → 外部系统）
- 限界上下文图（只表达领域边界/上下文关系，不混入系统调用）
- 核心领域模型图（聚合/实体/值对象/基数/关系）
- 逻辑/进程/开发/部署图
- 核心流程时序图 + 状态机（状态多的对象）
- 数据模型图（集合/字段/索引/关系）

**拆分规则**：系统调用关系与领域上下文关系不要画在同一张图；K8s 物理部署与网络/安全边界建议分开；时序图要标事务边界与异常分支。

**图语义硬规则**（详见 `figure-semantics.md`）：

- 部署图禁止把 infra 适配器/仓储/领域服务画成独立部署节点——它们是进程内代码层。
- 限界上下文图只画领域边界与关系模式，不画系统调用/消息总线。
- 时序图必须有事务边界（同步）与异步边界，至少一个异常/重试分支。
- 状态 ≥4 个的对象补状态机图；outbox 补事件流转图；账本补对账流程图。
- 每张图必须有图例，线型/颜色含义全文档一致。

## 限界上下文与集成图

- [ ] 每个上下文有边界框与一句话业务能力
- [ ] 上下文之间的关系有方向，并标关系模式（共享内核/客户-供应商/防腐层/发布语言）
- [ ] 上游/下游或保护方/被保护方清楚
- [ ] 外部系统单独分区，不混进内部上下文
- [ ] 连线可追踪，标签不压节点

## 部署图

- [ ] 分区（用户侧/集群/外部）、节点、部署物、副本、版本都标出
- [ ] 每条连线有协议/端口，端点落在节点本体
- [ ] 没有连线重叠、交叉需桥接或改线
- [ ] 标签不压节点、不压线
- [ ] 出网白名单单独标出
- [ ] 读完能回答：装在哪、几个副本、走什么协议、失败看哪

## 逻辑/进程/开发视图

- [ ] 每张图都回答它对应视图的问题
- [ ] 逻辑视图每个模块有职责/接口/依赖方向
- [ ] 进程视图有进程/并发/异步/锁/失败重启
- [ ] 开发视图有分层/目录/构建/测试，依赖方向单一
- [ ] 与正文表格一致

## 时序图

- [ ] 生命线 ≤5，消息只向下，返回/异步样式统一
- [ ] 至少一个条件片段；异常路径有落点
- [ ] 验收点标注与正文一致
- [ ] 无斜线、无标签压线
