# 05 · 标准架构文档骨架与映射

> 本技能不是自造结构。骨架对齐三个业界标准：
> - **arc42**（12 节架构文档模板）：<https://arc42.org/overview/>
> - **Kruchten 4+1 视图模型**：逻辑 / 进程 / 开发 / 物理视图 + 场景视图
> - **DDD 领域模型标准组成**：限界上下文、上下文映射、聚合、实体、值对象、领域事件、领域服务、仓储、工厂
>
> 本文给出标准骨架、与旧结构的差异、以及「文档控制信息」放哪。

| arc42 章节 | 本技能中的位置 | 说明 |

## 2. 4+1 视图的强制要求

| 视图 | 回答什么 | 必须包含 |
|---|---|---|
| 逻辑视图 | 系统由哪些构建块组成、各自职责与依赖 | 构建块图（每块有内容）+ 模块职责表 + 允许的依赖方向 |
| 进程视图 | 运行时进程/线程/协程、并发、异步、事务、失败重启 | 进程图 + 并发与隔离说明 + 事务边界 + 容量 |
| 开发视图 | 代码怎么组织、怎么构建、怎么测 | 包/模块图 + 目录结构 + 构建与测试分层 |
| 物理视图 | 装在哪、网络边界、副本与存储 | 部署图 + 部署表 + 探针/出网/扩缩容 |
| 场景视图 | 关键用例如何穿过各视图 | 用例 → 模块链 → 验收点的表（至少 4 个场景） |

## 3. DDD 领域模型的标准组成

| 元素 | 说明 | 图里怎么表示 |
|---|---|---|
| 限界上下文 | 模型边界与团队/语言边界 | 上下文框；上下文映射图 |
| 上下文映射 | 上下文之间的关系：共享内核、客户/供应商、遵奉者、防腐层、发布语言 | 上下文之间的箭头 + 关系模式标注 |
| 聚合 / 聚合根 | 一致性边界；外部只能通过聚合根访问 | 聚合框包住内部实体；根标 «aggregate root» |
| 实体 | 有唯一标识与生命周期 | 类框 + 标识字段 |
| 值对象 | 无标识、不可变、按值相等 | 类框 + «value object» |
| 领域事件 | 已发生的业务事实，用于跨聚合/跨上下文解耦 | 虚线箭头 + 事件名（过去式） |
| 领域服务 | 不属于单个实体/值对象的领域逻辑 | «domain service» 框 |
| 仓储 | 聚合的持久化抽象（每个聚合根一个） | «repository» 接口框 + 指向聚合的依赖 |
| 工厂 | 复杂聚合的创建逻辑 | «factory» 框 |
| 数据模型（ER） | 持久化实现视图，不是领域模型 | 表结构；只作为领域模型的一个子节 |

**常见错误**：把 ER 图当领域模型；只画实体字段不画聚合边界；领域事件画成同步调用；仓储和领域服务不出现；上下文集成没有防腐层/发布语言说明。

## 4. 文档控制信息放哪

- 文档定位、权威顺序、修订方式、构建/重建命令：放 **README 或文档控制页**，不占架构正文章节。
- 架构正文从「引言与目标」开始；「现状事实」并入「架构约束」并带依据。
- 多文档体系（总览/PRD/分册/计划）的权威顺序，属文档管理，放在 README 的「文档控制」一节。
