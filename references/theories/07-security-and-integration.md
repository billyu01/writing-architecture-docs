# 安全与集成：STRIDE / 信任边界 / OWASP / EIP

> 用途：把安全从「有认证」变成威胁建模与控制矩阵；把集成从「调接口」变成契约、幂等、重试、死信的完整方法。

## 1. 威胁建模（STRIDE）

### 1.1 定义
STRIDE 把威胁分为六类：欺骗（Spoofing）、篡改（Tampering）、否认（Repudiation）、信息泄露（Information Disclosure）、拒绝服务（DoS）、提权（Elevation of Privilege）。

### 1.2 使用步骤
1. 画数据流图/信任边界（用户、入口、服务、数据、外部）。
2. 对每个跨边界的数据流套 STRIDE 六类问题。
3. 为每个威胁写控制措施与残留风险。
4. 给风险分级（高/中/低），高风险必须有控制或接受理由。
5. 把控制落到设计（认证、授权、加密、审计、限流、隔离）。

### 1.3 威胁-控制矩阵模板
| 数据流 | 威胁 | 控制 | 残留风险 | 负责人 |
|---|---|---|---|---|
| 客户端→入口 | 欺骗/DoS | OIDC、限流、TLS | 凭据泄露 | 安全 |
| 服务→数据库 | 篡改/泄露 | 最小权限、加密、审计 | 内部越权 | 平台 |
| 服务→短信 | 信息泄露 | 脱敏、加密字段、密钥轮换 | 供应商留存 | 安全 |

### 1.4 检查清单
- [ ] 有信任边界图。
- [ ] 每个跨边界流有 STRIDE 分析。
- [ ] 每个威胁有控制与残留风险。
- [ ] 高风险有接受理由。
- [ ] 控制落到具体设计。

### 1.5 常见误用
- 只写认证不写授权；
- 只写「加密」不写密钥管理；
- 没有残留风险；
- 威胁不落到设计。

## 2. 信任边界与最小权限

### 2.1 定义
信任边界是不同信任级别的分界；跨边界必须认证、授权、校验、审计。最小权限是每个主体只拿完成任务所需的最小权限。

### 2.2 使用步骤
1. 画分区：公网、DMZ、内网、数据区、管理区。
2. 标每个边界的入口/出口与协议。
3. 为每个角色定义权限矩阵（操作 × 数据范围）。
4. 服务账号按最小权限授权。
5. 管理面与数据面分离；跨店访问走审批与审计。

### 2.3 检查清单
- [ ] 有信任边界图。
- [ ] 每个边界有认证/授权/校验/审计。
- [ ] 有角色权限矩阵。
- [ ] 服务账号最小权限。
- [ ] 门店范围来自服务端上下文，不信任客户端传参。

### 2.4 常见误用
- 内网默认可信；
- 用客户端传的 store_id 做隔离；
- 服务账号用管理员；
- 管理接口暴露公网。

## 3. OWASP ASVS（应用安全验证）

### 3.1 定义
OWASP ASVS 给出应用安全验证要求分级（L1/L2/L3），覆盖认证、会话、访问控制、输入校验、加密、错误处理、日志等。

### 3.2 使用步骤
1. 按系统风险选 ASVS 等级。
2. 把要求映射到设计条目与验收用例。
3. 高风险项（认证、访问控制、加密、注入）必须有实现与测试。
4. 上线前做安全测试/扫描。

### 3.3 检查清单
- [ ] 选定 ASVS 等级。
- [ ] 高风险要求有设计与测试。
- [ ] 有安全测试/扫描。
- [ ] 有漏洞修复流程。

## 4. 密钥与凭据管理

### 4.1 使用步骤
1. 凭据放 Secret/密钥管理服务，不入仓、不进镜像。
2. 定义轮换周期与责任人。
3. 应用滚动重启读取新凭据。
4. 加密密钥与哈希密钥分离；轮换时考虑索引迁移。
5. 审计每次轮换。

### 4.2 检查清单
- [ ] 凭据不入仓。
- [ ] 有轮换周期。
- [ ] 有轮换演练。
- [ ] 密钥分离。
- [ ] 有审计。

## 5. Enterprise Integration Patterns（EIP）

### 5.1 定义
企业集成常用模式集合：消息通道、发布订阅、幂等消费者、重试、死信、路由、聚合等。

### 5.2 关键模式
| 模式 | 用途 |
|---|---|
| 幂等消费者 | 重复消息不重复处理 |
| 重试/退避 | 临时故障恢复 |
| 死信队列 | 多次失败后隔离 |
| 发布订阅 | 一对多事件 |
| 消息路由 | 按内容/类型分发 |
| 关联标识 | 请求-响应/长流程关联 |

### 5.3 使用步骤
1. 明确同步还是异步；异步必须有幂等与重试。
2. 定义消息格式、版本、关联 ID。
3. 定义重试策略、最大次数、死信与人工重发。
4. 定义积压监控与告警。
5. 做重复/乱序/失败注入测试。

### 5.4 检查清单
- [ ] 同步/异步选择有理由。
- [ ] 消费方幂等。
- [ ] 有重试/退避/死信。
- [ ] 有积压监控。
- [ ] 有重复/乱序测试。

### 5.5 常见误用
- 忽略至少一次语义；
- 没有死信；
- 消息无版本；
- 同步调第三方却按可靠消息设计。

## 6. API 契约

### 6.1 使用步骤
1. 每个接口写方法、路径、鉴权、幂等、请求/响应、错误码。
2. 错误码统一信封：code、message、request_id、details。
3. 版本策略与兼容规则。
4. 分页/排序/过滤规范。
5. 契约测试与消费者驱动测试。

### 6.2 检查清单
- [ ] 接口清单完整。
- [ ] 鉴权/幂等/错误码齐全。
- [ ] 有版本与兼容规则。
- [ ] 有契约测试。

---

## 7. 与其他理论关系
- STRIDE/ASVS 支撑安全章节；信任边界与 C4 Context/Deployment 对应。
- EIP 支撑 outbox/消费/重试；幂等与一致性理论共享同一套语义。
- API 契约是逻辑架构接口与集成视图的落地。
