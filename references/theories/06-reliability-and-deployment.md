# 可靠性与部署：副本 / 故障域 / RPO-RTO / 可观测 / K8s 模式

> 用途：把「高可用」落到部署拓扑、故障域、切换、备份、容量与观测的完整方法。

## 1. 可靠性的基本手段

### 1.1 定义
可靠性 = 在规定条件下、规定时间内完成规定功能的能力；工程上通过冗余、隔离、检测、恢复实现。

### 1.2 手段
| 手段 | 作用 | 代价 |
|---|---|---|
| 副本 | 单点故障时接管 | 成本、一致性复杂度 |
| 故障域隔离 | 避免一处故障扩散 | 部署复杂度 |
| 健康检查/探针 | 发现故障实例 | 误判风险 |
| 自动切换 | 缩短恢复时间 | 切换抖动、脑裂风险 |
| 降级 | 保核心功能 | 功能缺失 |
| 限流/熔断 | 防止雪崩 | 部分请求失败 |
| 备份/恢复 | 防数据丢失 | 存储与演练成本 |

### 1.3 使用步骤
1. 列单点：应用、数据库、缓存、对象存储、第三方、DNS、证书。
2. 每个单点给冗余或降级方案。
3. 定义故障检测（探针、心跳）。
4. 定义切换与恢复流程。
5. 定义降级顺序与用户影响。
6. 做故障注入验证。

### 1.4 检查清单
- [ ] 单点清单完整。
- [ ] 每个单点有冗余/降级。
- [ ] 有检测与切换机制。
- [ ] 有降级顺序与用户影响说明。
- [ ] 有故障注入用例。

## 2. 故障域与副本

### 2.1 定义
故障域是可能同时故障的一组组件（进程、节点、机架、可用区、区域）。副本应跨故障域分布。

### 2.2 使用步骤
1. 识别故障域层级（进程→节点→机架→可用区→区域）。
2. 关键组件至少跨一个故障域冗余。
3. 数据库副本集跨节点/可用区；写主节点单点要显式说明。
4. 定义脑裂防护（多数派、仲裁）。
5. 验证：单节点故障、单可用区故障。

### 2.3 检查清单
- [ ] 关键组件跨故障域。
- [ ] 数据库副本分布明确。
- [ ] 写主节点单点已说明。
- [ ] 有脑裂防护。
- [ ] 有故障域级演练。

## 3. RPO / RTO 与备份恢复

### 3.1 定义
- RPO（恢复点目标）：最多丢多少数据（时间）。
- RTO（恢复时间目标）：多久恢复服务。

### 3.2 使用步骤
1. 按业务定 RPO/RTO（资金/积分通常更严）。
2. 选备份方式（全量/增量/连续归档）与频率。
3. 写恢复流程、责任人、演练频率。
4. 验证：恢复演练、数据校验。
5. 平台托管数据库要拿到书面承诺，不能假设。

### 3.3 检查清单
- [ ] RPO/RTO 有业务依据。
- [ ] 备份方式/频率/保留期明确。
- [ ] 恢复流程有步骤与责任人。
- [ ] 有恢复演练记录。
- [ ] 托管服务承诺已核实。

### 3.4 常见误用
- RPO/RTO 拍脑袋；
- 有备份没恢复演练；
- 把平台能力当自有能力。

## 4. 可用性计算与 SLO

### 4.1 定义
可用性 = 可用时间 / 总时间；常用 99.9%（月停 43 分钟）、99.95%（月停 21 分钟）。

### 4.2 使用步骤
1. 定义统计窗口与排除项（计划维护）。
2. 用串联/并联估算：串联可用性相乘，冗余并联提高。
3. 把目标拆到关键链路与依赖。
4. 与 SLO/错误预算对齐（见 03）。
5. 验证：监控实际可用性。

### 4.3 检查清单
- [ ] 可用性目标有窗口与排除项。
- [ ] 关键依赖的可用性已核算。
- [ ] 目标与 SLO 一致。
- [ ] 有实际测量。

## 5. 部署拓扑与 K8s 模式

### 5.1 部署单元映射
- 逻辑模块 → 进程/容器/Pod/函数。
- 合并/拆分依据：扩缩容、故障隔离、安全边界、团队边界。

### 5.2 K8s 常用对象
| 对象 | 作用 |
|---|---|
| Deployment | 无状态副本、滚动更新 |
| StatefulSet | 有状态、稳定标识 |
| Service | 服务发现/负载均衡 |
| Ingress | 入口/TLS |
| ConfigMap/Secret | 配置/密钥 |
| HPA | 水平扩缩 |
| NetworkPolicy | 网络访问控制 |
| ServiceAccount | 最小权限 |

### 5.3 使用步骤
1. 画分区：用户侧/入口/集群/数据/外部。
2. 每个部署单元标镜像、副本、资源、探针。
3. 画网络路径：协议、端口、方向、白名单。
4. 配 HPA 指标（CPU/队列/延迟）。
5. 配 NetworkPolicy 与 Secret。
6. 写发布/回滚策略。

### 5.4 检查清单
- [ ] 每个单元有镜像/副本/资源/探针。
- [ ] 网络路径有协议/端口/方向。
- [ ] 有 HPA 指标。
- [ ] 有 NetworkPolicy。
- [ ] 有发布/回滚策略。
- [ ] 没有把进程内层画成部署节点。

## 6. 可观测性

### 6.1 三支柱
日志（结构化）、指标（分位/错误率/饱和）、追踪（请求链路）。

### 6.2 使用步骤
1. 每个核心链路定义关键指标。
2. 日志带请求号、模块、事件、耗时，禁止明文敏感信息。
3. 追踪跨服务/跨异步任务。
4. 告警分级：快烧/慢烧/容量。
5. 看板按角色组织（开发/运维/业务）。

### 6.3 检查清单
- [ ] 核心链路有指标。
- [ ] 日志结构化、无敏感信息。
- [ ] 有追踪。
- [ ] 告警有阈值与处置。
- [ ] 有看板。

## 7. 与其他理论关系
- 4+1 物理视图承载部署拓扑；C4 Deployment 提供表达；SRE 提供 SLO/错误预算；质量场景提供验收。
- CAP/PACELC 决定故障时的取舍；DDD 聚合决定数据一致性边界。
