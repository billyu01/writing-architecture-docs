# 02 · 文档体系、权威顺序与可维护性

## 1. 一次架构交付通常包含哪些文档

| 文档 | 回答什么问题 | 权威级别 | 变更方式 |
|---|---|---|---|
| 架构总览 | 系统全貌：域、层、组件、流程、部署、决策、安全、扩展 | **最高（唯一权威）** | 正常修订，旧版加取代横幅 |
| PRD / 需求规格 | 做什么、为谁做、怎样算成功 | 高（需求侧权威） | 正常修订，保留差异表 |
| 技术选型 | 用什么、哪个版本、怎么集成、怎么升级 | 高 | 版本变更需记录实测依据 |
| 模块分册 | 每个模块的职责、接口、数据、验收 | 中（受总览约束） | 随实现更新，标注状态 |
| 实施计划 | 怎么落地、任务怎么切、文件归谁 | 中（执行侧） | 随开发更新 |
| 决策台账 / 裁定文档 | 为什么改方向、谁拍的板、怎么恢复 | 高（历史事实，不可改写） | 只追加，不改历史条文 |
| 图资产 | 结构与流程的可视表达 | 中（受正文约束） | 改图源后重建，不手改产物 |

## 2. 权威顺序（必须显式写进文档）

写法模板：

```markdown
> **文档权威顺序**：架构总览（本文） > PRD > 技术选型 > 模块分册 > 实施计划 > 过程台账。
> 历史文档保留作依据；与本文冲突时以本文为准。
```

规则：
- 全局只允许**一套**权威顺序。PRD 里若也写了一套，必须与总览一致；不一致就是缺陷。
- 低层文档必须声明「以某份为准」，不能都自称权威。
- 换代时四样同时更新：**取代横幅、权威顺序表、修订史、图索引**。

## 3. 编号与追溯

| 对象 | 编号 | 存在哪里 | 追溯方向 |
|---|---|---|---|
| 功能需求 | `FR-<域>-<序号>` | PRD | FR → 模块分册节 → 验收点 |
| 非功能需求 | `NFR-<序号>` | PRD | NFR → 设计措施 → 验证方式 |
| 验收关卡 | `GATE-<域>-<序号>` | PRD/计划 | GATE → 判据 → 执行位置 |
| 技术决策 | `D<序号>` | 架构总览/ADR | D → 影响章节/代码/部署 |
| 待决事项 | `OPEN-<序号>` | 待决策清单 | OPEN → 默认走法 → 关闭裁定 |
| 用户裁定 | `#<序号>`（或日期） | 裁定台账 | 裁定 → 受影响文档逐处标注 |

追溯表模板（阶段 4 产出）：

| 需求 | 设计落点 | 验收点 | 状态 |
|---|---|---|---|
| FR-XXX-1 | 架构 §x / 模块 NN §y | GATE-XXX-1 | 覆盖 |

规则：**集合相等优于计数相等**。判断「工具是否齐全」用逐名白名单集合相等，不用「一共 N 个」——组合一变，计数断言就会骗过。

## 4. 锚点纪律（文档与代码对齐）

- 优先写「**文件 + 符号名**」（类/函数/常量），行号只作辅助。
- 必须写行号时，标实测日期，并写明「行号会随编辑漂移，以引文为准」。
- 行号漂移是常态。批量回写按模式分类（例如：插块导致整段偏移 / 另一文件小幅偏移 / 状态陈述过时 / 数量小修），每类给根因，只改行号与状态词，**不得改技术判断**。
- 回写前先 `git fetch` + 看工作树，避免与并发改动互相覆盖。
- 每册头部记修订：改了什么、为什么、增删行数。
- 状态词（「未实现/未合并/未提交/不存在」）必须带当日证据；换日复审时重跑。

## 5. 修订史与取代

总览必修史模板：

```markdown
### 修订史

- YYYY-MM-DD：初版（整合自 A/B/C 三份底稿）
- YYYY-MM-DD：<一句变更>（依据：用户裁定 #N / 评审结论）
- YYYY-MM-DD：<一句变更>（取代旧文档 X；旧文档已加取代横幅）
```

旧文档处理：
- 头部加横幅：`> 〔已被取代 YYYY-MM-DD〕本文被 <新文档> 取代，保留作历史依据；引用请改为新权威。`
- **原文不删**。历史结论被删掉，后人无法判断「当时就这么错」还是「后来改对」。
- 作废项登记：作废对象、依据、tip 提交号、恢复命令。不能恢复的写「不可逆」。

## 6. 生成物的可重建性

任何「可视权威版」都必须满足：

1. 源（图/模板）与生成物分离；
2. 构建脚本在仓库里，命令写进文档；
3. 构建可重复：连跑两次字节一致；
4. 构建前有断言：无未替换占位符、图数正确、id 全局唯一；
5. **生成物永不手改**；改了源就重新构建。

反例（真实）：文档第 6 行声称可用某脚本重建 HTML，但该脚本在后续提交里被删除，当前仓库已无此文件，产物实际不可重建。检查方法：`grep -n "重建\|rebuild\|python3 tools/" 文档`，再逐个 `test -f` 验证。

## 7. 目录约定（建议）

```
docs/
  architecture/
    <date>-<系统>-架构设计.md        # 唯一权威总览
    <date>-<系统>-架构设计.html      # 可视权威版（可选，脚本重建）
    modules/NN-<模块>.md             # 模块分册
    assets/                          # ER/时序/部署图源（html/svg/png）
    decisions/                       # ADR 或决策台账
  prd/<date>-需求规格.md
  specs/<date>-技术选型.md
  plans/<date>-实施计划.md
```

命名带日期，避免多版本同名并存；文件头写状态（草稿/评审中/生效/被取代）。
